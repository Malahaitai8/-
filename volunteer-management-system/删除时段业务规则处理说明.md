# 删除时段业务规则处理说明

## 问题描述
当用户尝试删除活动的最后一个时段时，数据库触发器/约束会阻止删除操作，但前端显示的是通用的500错误，用户体验不好。

## 业务规则
**每个活动至少需要保留一个时段**，这是数据库层面的业务约束。

## 错误信息
数据库返回的原始错误：
```
操作失败：事件 ACT000000000070 至少需要一个时段。不能删除其最后一个时段 (TSL000000000009)。
```

## 解决方案

### 1. 后端改进 (VolunteerActivityController.java)
```java
// 新增专门的DataAccessException处理
catch (org.springframework.dao.DataAccessException e) {
    String errorMessage = e.getMessage();
    
    // 检查是否是业务规则约束错误
    if (errorMessage != null && (errorMessage.contains("至少需要一个时段") || 
        errorMessage.contains("不能删除其最后一个时段") ||
        errorMessage.contains("需要一个时段"))) {
        return Result.error("400", "无法删除：每个活动至少需要保留一个时段");
    }
    
    return Result.error("500", "删除时段失败");
}
```

### 2. 前端改进 (Organization-ActivityDetail.vue)
```javascript
// 改进错误处理，显示后端返回的具体错误信息
if (error.response && error.response.data && error.response.data.msg) {
  ElMessage.error(error.response.data.msg)
} else {
  ElMessage.error('删除时段失败: ' + error.message)
}
```

## 修复后的效果

### 修复前
- ❌ 显示"500 删除时段失败"
- ❌ 用户不知道具体原因

### 修复后  
- ✅ 显示"无法删除：每个活动至少需要保留一个时段"
- ✅ 用户清楚了解业务规则
- ✅ 错误码改为400（客户端错误）而不是500（服务器错误）

## 用户体验改进
1. **明确的错误提示** - 用户知道为什么不能删除
2. **业务规则透明** - 用户了解系统的业务约束
3. **合适的错误码** - 400表示用户操作不当，而非系统故障

## 测试场景
1. **删除非最后时段** - 正常删除成功
2. **删除最后时段** - 显示友好的业务规则提示
3. **删除不存在的时段** - 显示"时段不存在"
4. **删除其他活动的时段** - 显示"时段不属于该活动"
