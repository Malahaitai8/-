# 日期格式修复说明

## 问题描述
在添加时段功能时，后端出现以下错误：
```
JSON parse error: Cannot deserialize value of type `java.util.Date` from String "2025-06-25 00:00:00": not a valid representation
```

## 问题原因
前端发送的日期格式是 `"2025-06-25 00:00:00"`，但后端Jackson默认期望ISO 8601格式（如 `"2025-06-25T00:00:00"`）。

## 解决方案
在实体类的日期字段上添加 `@JsonFormat` 注解来指定正确的日期格式。

### 修改的文件

#### 1. ActivityTimeslot.java
```java
@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")
private Date startTime;

@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")
private Date endTime;
```

#### 2. VolunteerActivity.java
修复了错误的日期格式模式：
- 将 `"yyyy-MM-DD HH:mm:ss"` 改为 `"yyyy-MM-dd HH:mm:ss"`
- （大写D表示一年中的第几天，小写d表示月中的第几天）

## 修复后的效果
- ✅ 添加时段功能正常工作
- ✅ 删除时段功能正常工作  
- ✅ 活动详情编辑功能的日期字段正常工作
- ✅ 前后端日期格式统一

## 注意事项
- 时区设置为 `GMT+8`（中国标准时间）
- 日期格式为 `yyyy-MM-dd HH:mm:ss`
- 前端需要确保发送的日期字符串格式与后端期望的格式一致
