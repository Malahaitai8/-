# 删除时段错误处理修复说明

## 问题描述
用户反映在删除活动的最后一个时段时，虽然数据库触发器正确阻止了删除操作并返回了具体的错误信息，但前端只显示"400"错误码，而不是友好的业务提示信息。

## 数据库触发器错误消息
根据数据库触发器脚本 `05_triggers/01_organization_trigger.sql`，第259行定义的错误消息格式为：
```sql
N'操作失败：事件 ' + @EventID_ToProcess + N' 至少需要一个时段。不能删除其最后一个时段 (' + @TimeslotID_ToProcess + N')。'
```

## 修复内容

### 1. 后端Controller修复
**文件**: `VolunteerActivityController.java`
**位置**: `deleteTimeslot` 方法的异常处理部分

**修复前的问题**:
- 只检查简单的关键词匹配
- 没有检查嵌套异常的错误信息
- 错误消息匹配不够精确

**修复后的改进**:
```java
} catch (org.springframework.dao.DataAccessException e) {
    // 处理数据库访问异常
    String errorMessage = e.getMessage();
    System.err.println("Error deleting timeslot ID: " + timeslotId + " for activity ID: " + activityId + "; Error: " + errorMessage);
    
    // 获取根本原因异常信息
    Throwable cause = e.getCause();
    String causeMessage = cause != null ? cause.getMessage() : "";
    System.err.println("Root cause: " + causeMessage);
    
    // 检查是否是业务规则约束错误（至少需要一个时段）
    // 数据库触发器错误消息：操作失败：事件 {ID} 至少需要一个时段。不能删除其最后一个时段
    String fullErrorText = errorMessage + " " + causeMessage;
    if (fullErrorText.contains("操作失败：事件") && fullErrorText.contains("至少需要一个时段") ||
        fullErrorText.contains("不能删除其最后一个时段") ||
        fullErrorText.contains("至少需要一个时段") ||
        fullErrorText.contains("需要一个时段")) {
        return Result.error("400", "无法删除：每个活动至少需要保留一个时段");
    }
    
    return Result.error("500", "删除时段失败");
}
```

**主要改进点**:
1. **嵌套异常检查**: 增加了对 `e.getCause()` 的检查，获取SQL Server原始错误信息
2. **完整错误文本**: 将主异常和嵌套异常的信息合并进行检查
3. **精确匹配**: 增加了对完整触发器错误消息格式的匹配
4. **详细日志**: 增加了根本原因的日志输出，便于调试

### 2. 错误匹配策略
修复后的代码使用多层次的错误匹配策略：

1. **完整格式匹配**: `"操作失败：事件" + "至少需要一个时段"`
2. **关键片段匹配**: `"不能删除其最后一个时段"`
3. **兜底匹配**: `"至少需要一个时段"` 或 `"需要一个时段"`

## 技术原理
SQL Server的 `RAISERROR` 触发器错误通过JDBC驱动传递到Spring Boot时，通常会被包装在多层异常中：
```
DataAccessException
  └── SQLServerException (getCause())
      └── 实际的触发器错误消息
```

因此需要检查嵌套异常才能获取到完整的错误信息。
